# Delivery sequence

The active user goal is the finished water-surface experience, portfolio intro and separate experimentation page. Research gates protect that delivery; they do not replace it.

1. Complete Stage 1 same-field shading comparison, motion records, independent validity and visual reviews.
2. Choose the smallest justified next surface change. If slope shading is insufficient, conduct the signed-profile comparison with the accepted transfer fixed. Avoid deciding based only on more contrast or a still.
3. Integrate the supported surface as a reusable renderer with explicit lifecycle, deterministic intro cue and pointer/touch disturbances. Preserve resume content and existing links/print. Add a dedicated no-resume experience route with a few meaningful controls, reset/pause and navigation back.
4. Verify actual desktop/mobile browser flows, intro/reduced-motion behavior, resize, context loss/fallback, resource disposal and runtime limits. Separate software-renderer evidence from real-device performance.
5. Deliver working code, reviewable build and evidence; update the existing Drive review folder. Mark the active goal complete only when all user-facing requirements are implemented and verified, with material limitations stated.

No final production surface is selected at this stage. Existing incumbent visual language is a paper-like pale background with Figtree interface typography and serif resume headline. The new opening and playground extend that language; no unrelated resume rebrand is needed to satisfy this goal.
